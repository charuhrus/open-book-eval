# Open-book registry assistant: LLM eval suite

A hands-on project for learning how to test LLM features. It evaluates a small support assistant that must answer questions about a (fictional) carbon-credit registry **using only a supplied document**, and say "I don't know" when the document doesn't cover the question.

Everything runs locally: the model under test and the judge are both `llama3.2:3b` on [Ollama](https://ollama.com), driven by [Promptfoo](https://promptfoo.dev). No API keys, no per-run cost, and no model output leaves the machine.

## Prerequisites

- **Node.js 22.22 or newer** (developed on v24). Promptfoo refuses to start on older versions.
- **Ollama** running locally, with the model pulled:

  ```bash
  ollama pull llama3.2:3b
  ```

  Use the full `name:tag`. Ollama matches tags exactly, so `llama3.2` looks for `llama3.2:latest` and fails with a 404 if only `:3b` is installed.
- Optional: `npm install` adds `@types/node`, which is only needed for editor type-checking. Promptfoo itself runs through `npx`.

## Running it

```bash
# Main eval
npx promptfoo@latest eval

# Browse results, including per-assertion reasons from the judge
npx promptfoo@latest view

# Measure run-to-run variation (cached runs reuse old outputs and hide it)
npx promptfoo@latest eval --no-cache --repeat 3

# Run a single test while iterating
npx promptfoo@latest eval --filter-pattern "CORSIA"

# Test the judge itself (see "Grading the grader" below)
npx promptfoo@latest eval -c judge-check.yaml

# Unit tests for product code, and a type-check of all TypeScript
node --test src/feeCalculator.test.ts
npx -p typescript tsc
```

## The test suite

The document is five numbered rules (fees, settlement time, buffer pool, CORSIA eligibility) defined once in `defaultTest.vars.document`. Each test asks one question against it.

| Test | What it probes | How it's checked | Baseline (`--repeat 3`) |
|---|---|---|---|
| Retirement fee | Simple lookup of a number | `assertions/retirementFee.ts` | 3/3 |
| Settlement time | Simple lookup of a phrase | `icontains` | 3/3 |
| Buffer pool | Lookup, graded on meaning | `contains` + `llm-rubric` (from `cases/`) | 3/3 |
| Issuance fee | **Hallucination trap**: the fee isn't in the document | `not-regex` for 0.05 + `llm-rubric` for a refusal | 3/3 |
| CORSIA, 2015 vintage | **Negation rule**: "earlier than 2016 cannot be used" | `not-icontains "don't know"` + `regex` for no/cannot | 0/3 |
| First-year fees | **Multi-fact arithmetic**: 500 + 1,000 × 0.05 | `regex` for 550 + `llm-rubric` | 0/3 |

The two failures are real model defects, not test problems:

- **CORSIA:** in 2 of 3 runs the model quotes rule 5 correctly and still opens with "I don't know". The strict refusal instruction overrides its own correct reading.
- **First-year fees:** it lists 500 USD and 50 USD but never adds them up.

## Design decisions

**Pin the judge.** With no grader configured, Promptfoo looked for any available credentials and found a Codex login in `~/.codex`, so `llm-rubric` outputs were silently sent to OpenAI. When that quota ran out, grader crashes were reported as test **failures** with "0 errors" in the summary. The judge is now set explicitly in `defaultTest.options.provider` (local, `temperature: 0`).

**Deterministic checks first, rubrics only for meaning.** Anything with a right answer (a number, a required or forbidden phrase) uses a string, regex or code check. `llm-rubric` is kept for things code can't judge, like whether an answer is a genuine refusal.

**Assertions are tested too.** `retirementFee.ts` converts every amount in the output to USD (handling `$.05`, `USD 0.050`, `five cents`, and so on) and passes only if 0.05 USD appears **and** every amount is a figure from the document. That second condition catches invented arithmetic like "1 + 0.05 = 1.05 USD", which an earlier "any amount matches" rule let through. The logic was checked against an 18-case Node test list of answers that must pass and answers that must fail, including near-misses like `0.05 cents`, `10.05 USD` and `twenty five cents`.

**Grading the grader.** `judge-check.yaml` uses Promptfoo's `echo` provider, so the "model output" is exactly a labelled answer. Five answers (two that should pass, three that should fail) go through the real buffer-pool rubric, and the judge has to agree with every label. Current agreement: 15/15 over repeated runs. Three judge bugs were found this way: an inverted assertion, a judge that copied the rubric, and a judge that couldn't see the question.

**One source of truth for each case.** The buffer-pool question and rubric live in `cases/bufferPool.ts`. The main eval and the judge check both import them, so the judge is always tested against the exact rubric the eval uses.

**Arithmetic belongs in code.** Three prompt variants were measured for the first-year question:

| Prompt variant | First-year pass rate | Side effects |
|---|---|---|
| No calculation instruction | 0/5 | none |
| "Show amounts and total" | 6/8 | Invented "1 + 0.05 = 1.05 USD"; confused the trap answer |
| "Total only if asked" | 1/5 | none |

A 3B model can't follow conditional arithmetic instructions reliably, so the arithmetic moved to `src/feeCalculator.ts`. It works in integer cents and throws a `RangeError` on invalid input (negative, fractional, zero years) instead of clamping, because a fee calculator should never guess.

**The judge stays small, on purpose.** A `qwen2.5:7b` judge was more accurate but took about 7.5 minutes per run and made an 8 GB Mac unusable. Narrow rubrics plus deterministic backstops made the 3B judge reliable enough, and the judge check proves it.

## Gotchas worth knowing

- **`file://` templating is inconsistent.** Prompt files loaded with `file://` have `{{vars}}` filled in. `llm-rubric` values loaded with `file://` do **not**: the judge receives a literal `{{question}}`. Both were confirmed in debug logs. That's why `cases/bufferPool.ts` builds its rubric with a TypeScript template string instead.
- **A judge only knows what's in the rubric.** It doesn't see the document or the question unless the rubric includes them. "Is this supported by the document?" needs the document in the rubric; "does it refuse?" doesn't.
- **Caching hides non-determinism.** Promptfoo caches model and judge responses. That's ideal while working on assertions, since the outputs stay fixed, but use `--no-cache` whenever you want to measure behaviour.
- **Errors are not failures.** An error means the test never ran properly (missing model, grader outage). Check the logs before reading a failure as a model regression.
- **Read results per test, not only the headline.** The overall pass rate stayed around 67% across several changes while individual tests flipped underneath.
- **YAML quoting.** Quote expected values like `'0.05'` (otherwise YAML reads a number). Inside a single-quoted YAML string, an apostrophe is written twice: `can''t`.

## Roadmap

- **CORSIA prompt A/B.** Add `src/prompts/assistant-v2.txt` ("check each numbered rule first; only reply I don't know if no rule applies"), list both prompts under `prompts:`, and run `--no-cache --repeat 5`. CORSIA should improve; the issuance-fee trap must stay at 5/5.
- **Tool calling.** A custom provider (`src/feeAssistant.ts`) that gives the model a `calculateFees` tool. Evaluate in two layers: did it call the tool with `years: 1, retirements: 1000`, and does the final answer state 550 USD. Move the money parser into a shared helper so the 550 check can reuse it.
- **Break tests on purpose.** Change `EXPECTED_USD`, weaken the prompt, and confirm each test fails for the right reason.
- **Pass-rate write-up.** Per-test pass rates from repeated runs, and the case for thresholds over single pass/fail.
- **Single-source the remaining rubrics** (trap, first-year) in `cases/`, each with its own judge check.
- **Housekeeping.** Optionally `ollama rm qwen2.5:7b` (4.7 GB); decide whether `tweets.yaml` stays.
